## P0 — Visible defects

### 1. The globe's lat/lon grid paints pure white in light mode

`js/globe.js` `_buildGrid()` (line 642) builds the graticule with
`blending: AdditiveBlending`. Additive blending adds source to destination, which
reads as a glow on a dark sphere and **saturates to white on a light one**.

The light palettes already define correct grid colours — apricot light has
`grid: '#caa285'`, `gridBright: '#a05a30'` — and additive blending discards them
entirely:

```
land #dcc1a6 = (220,193,166)
grid #caa285 = (202,162,133), material opacity 0.20
result = (220,193,166) + 0.20·(202,162,133) = (255,225,193)   ← lighter than the land
```

The line always ends up *lighter* than the surface it is drawn on, so on a cream
globe it is a white line on cream — the exact opposite of the authored intent.

Verified by cropping and 3× nearest-neighbour upscaling the same region of the globe
in both themes: dark shows orange-brown grid lines, light shows white ones.

The same `AdditiveBlending` is used at lines 619 (atmosphere halo), 731 (pin pulse
ring), 779 / 784 (trip arcs) and 816 / 827 (pin glow). Those still read in light mode
because their colours are saturated, but they are all washed out for the same reason
and are worth revisiting together.

**Fix:** choose the blend mode from the resolved theme — `AdditiveBlending` for dark,
`NormalBlending` for light — so the light palette's authored grid colours are actually
used. One conditional in `_buildGrid()` covers the visible case.

### 2. The Europe map renders at 1× on every HiDPI display

`js/europe-map.js` `_resize()` (lines 127–128):

```js
this.canvas.width  = containerW;   // CSS pixels
this.canvas.height = containerH;
```

No `devicePixelRatio` anywhere in the file. It is the **only** canvas module without
it — every other one caps a real DPR:

| Module | DPR handling |
|---|---|
| `js/cnn-hero.js` | `min(dpr, 1.75)` |
| `js/globe.js` | `min(dpr, cap)` — 1.2 low-power / 1.7 |
| `js/neural-net.js` | `min(dpr, 1.25 \| 1.75)` |
| `js/mnist-lab.js` | `min(dpr, 2)` |
| `js/noise-gradient.js` | `min(dpr, 1.0)` — deliberate, it is a blurred gradient |
| **`js/europe-map.js`** | **none** |

Measured at `deviceScaleFactor: 2` on `/travel.html`:

```
globe-canvas   css 524×458   buffer 655×572   ratio 1.25
europe-canvas  css 524×458   buffer 524×458   ratio 1.00   ← half resolution
```

The map's coastlines are hairlines, which is the worst case for this — they are the
first thing to go soft. Every retina laptop and every phone gets a blurry map.

**Fix:** scale the backing store by a capped DPR in `_resize()` and scale the context
to match. Note `_bindEvents()` already converts pointer coordinates through
`canvas.width / rect.width`, so hit-testing follows automatically; `_lonToX` /
`_latToY` would need the same factor applied once.

## P1 — Accessibility

### 3. Small text on cards fails WCAG AA in every palette and both themes

This is the largest finding by volume and it has a clean root cause.

`test/contrast.test.mjs` is a genuinely good test, but it measures every text token
against **`bg` and `bgAlt`** — the page backgrounds. Almost none of the failing text
sits on those. It sits on `--bg-card`, which is `text` at 12% over `bg` and is
therefore *lighter* than `bg` in dark mode. A colour that just clears the bar against
the page drops below it on a card.

Two further gaps compound it:

- `--text-faint` is exempted to a **3:1** floor, justified as "large/incidental". But
  it is used at **10.9–13.1px** (`.link-card-host` 0.74rem, `.tl-location` 0.7rem,
  `.contact-label` 0.7rem, `.links-count`). WCAG's 3:1 large-text exemption requires
  ≥24px, or ≥18.66px bold. None of these qualify — they need 4.5:1.
- Accents are checked "as text and as graphics" at 3:1, but `.pub-venue`
  (`var(--accent2)`), `.tl-tag` and `.project-tag` (`var(--accent)`) are small text.

Computed straight from `data/palettes.yaml` + `SURFACE_ALPHA` — no browser needed,
so this is directly testable in `npm test`:

| palette / variant | textFaint : bg | textFaint : **card** | textMuted : cardHover | accent2 : card | accent : card |
|---|---|---|---|---|---|
| forest / dark | 4.78 ✅ | **3.55** ❌ | **3.78** ❌ | 5.44 ✅ | 5.88 ✅ |
| forest / light | 3.61 ✅ | **2.85** ❌ | **4.21** ❌ | **3.71** ❌ | **3.41** ❌ |
| apricot / dark | 4.52 ✅ | **3.36** ❌ | **4.08** ❌ | **4.50** ~ | 6.75 ✅ |
| apricot / light | 3.48 ✅ | **2.74** ❌ | **4.22** ❌ | **3.66** ❌ | **3.74** ❌ |
| crimson / dark | 4.61 ✅ | **3.45** ❌ | **3.95** ❌ | **3.40** ❌ | **3.21** ❌ |
| crimson / light | 3.44 ✅ | **2.70** ❌ | **4.33** ❌ | **4.39** ~ | **4.69** ✅ |

(✅ = ≥4.5:1, the AA floor for text under 24px.)

The `textFaint : bg` column is what the shipped test measures, and it passes. The
`textFaint : card` column is what visitors actually see.

In **light mode, `--text-faint` on a card is 2.70–2.85:1** — it fails even the 3:1
floor the test does apply.

Browser measurement agrees with the arithmetic to within 0.03 (apricot/dark
`.link-card-host` measured 3.33:1, computed 3.36:1), so the two methods corroborate
each other.

Worst offenders, measured on the rendered pages:

| Component | Token | Size | Worst ratio | Pages |
|---|---|---|---|---|
| `.contact-label` | `--text-faint` | 11.2px | **2.41:1** | index |
| `.link-card-host` | `--text-faint` | 11.8px | **2.69:1** | links (×49) |
| `.tl-location` | `--text-faint` | 11.2px | **2.69:1** | cv |
| `.unesco-count` | `--text-muted` on `--bg-card-hov` | 12.8px | **2.70:1** | travel |
| `.project-tag` | `--accent` | 10.6px | **2.87:1** | index, projects, all project pages (×75) |
| `.tl-tag` | `--accent` on 11% accent tint | 10.2px | **2.91:1** | cv |
| `.pub-venue` | `--accent2` | 13.1px | **2.71:1** | index, publications (×31) |
| `A.unesco-site` | link colour | 15.1px | **3.25:1** | travel (×109) |

Failure counts per configuration (deduplicated by component in brackets):

```
(default)/dark    72  [ 6]      (default)/light   406  [29]
forest/dark      187  [14]      forest/light      446  [32]
apricot/dark      72  [ 6]      apricot/light     404  [29]
crimson/dark     380  [19]      crimson/light     231  [23]
```

**crimson/dark and forest/light are materially worse than the default** — worth
knowing, since the palette picker makes all four reachable by any visitor.

**Fix, in order of leverage:**
1. Extend `test/contrast.test.mjs` to measure `text`, `textMuted`, `textFaint`,
   `accent` and `accent2` against `surfaces(p).card` and `.cardHover`, not only `bg`.
   The file already computes those surfaces for its ΔL tests.
2. Drop the `textFaint` 3:1 exemption, or stop using `--text-faint` below 24px.
3. Darken/lighten `textFaint`, `textMuted` and the accents per palette until the new
   assertions pass.

*Caveat:* one reported failure, `.link-chip.is-active` at 1.00:1, is a **false
positive** — the chip is filled with `linear-gradient(--accent, --accent2)`, which
`getComputedStyle().backgroundColor` cannot report. Screenshotted and confirmed
legible (dark text on orange). It is excluded from the counts above.

### 4. Touch targets below the WCAG 2.2 AA 24×24px minimum

Measured at 390px on every page. Standalone (non-inline) controls that fall short:

| Target | Size | Where |
|---|---|---|
| `.unesco-site` links | ~21px tall | travel.html, ×109 |
| `.cv-back-link` ("← Back to Home") | 102×22 | every sub-page |
| `.footer-social` links | 44×22, 56×22, 92×22 | every page |
| "Claude" footer link | 42×17 | every page |

**Fix:** a little vertical padding on `.unesco-site`, `.cv-back-link` and
`.footer-social a` — the spacing exception means padding counts toward the target
even if the text box stays the same.

## P3 — Code quality, dead weight, latent bugs

### 7. `js/europe-map.js` ships on every page

`js/main.js:56` imports it **statically**:

```js
import './europe-map.js';
```

`globe.js`, `cnn-hero.js`, `neural-net.js` and `mnist-lab.js` are all correctly
dynamic. This one is not, so its chunk is in the eager module graph of every page.
Measured per-page requests:

```
/index.html              … theme.js  europe-map.js  utils.js  main.js
/cv.html                 … theme.js  europe-map.js  utils.js  main.js
/links.html              … theme.js  europe-map.js  utils.js  main.js
/projects/traction.html  … theme.js  europe-map.js  utils.js  main.js
/travel.html             … theme.js  europe-map.js  utils.js  main.js  globe.js
```

10.2 KB fetched, parsed and executed on 20 pages that have no `#europe-canvas`. This
contradicts the loading strategy documented at the top of `main.js` and in
`CLAUDE.md`.

**Fix:** move it into `buildEurope()` as `import('./europe-map.js')`, mirroring
`buildGlobe()`. `main.js` currently reads `EuropeMap2D` as a bare global (set by the
module's side effect at `europe-map.js:650`), so switch to the named export at the
same time.

### 8. `dist/` publishes ~356 KB of build-time-only data

`copyDataJson()` in `vite.config.js` copies **every** `.json` in `data/`, but its own
comment names only the two that are fetched at runtime:

| File | In `dist/` | Fetched at runtime? |
|---|---|---|
| `land-50m.json` | 545 KB | yes — `europe-map.js` |
| `world-110m.json` | 55 KB | yes — `globe.js` via `getTopoJSON()` |
| `cnn-model.json` | **237 KB** | **no** — build-time only; the browser gets int8 `lenet-weights.js` |
| `countries-110m.json` | **108 KB** | **no** — consumed by `generate-world-map`, output inlined as SVG |
| `cnn-samples.json` | **11 KB** | **no** — bundled by Rollup as `cnn-samples-*.js` |
| `package.json` | 23 B | no — the `{"type":"module"}` stub |

No page requests them, so there is no cost to visitors — but the deploy carries a
third of a megabyte of dead weight, including the raw float32 training weights.

**Fix:** replace the `.endsWith('.json')` filter with an explicit allowlist of the two
runtime files. That also makes the plugin self-documenting.

### 9. `initTimelineScroll3D()` is dead code — and would violate the reveal invariant

`js/animations.js:314` looks for `#timeline-stage`, then `.tl-entry` inside it.
**Neither exists in any shipped HTML.** `renderCV()` produces `#cv-timeline`
containing `.tl-row` / `.tl-concurrent-block`. The only occurrences of
`timeline-stage` and `.tl-entry` in the repository are in the tests that mock them
(`test/main.node.test.mjs:1195`, `test/cv.test.mjs:367`).

So the function returns at line 318 on every page, and its tests only ever exercise
the mock.

This matters beyond tidiness. If it were ever reconnected, lines 338–341 do exactly
what `CLAUDE.md` warns against:

```js
entries.forEach(el => {
  el.style.opacity = '0';     // hidden unconditionally
  io.observe(el);             // revealed only by the observer
});
```

No sweep, no fallback. An entry already scrolled past on arrival never gets an
`isIntersecting` callback and stays invisible permanently — the identical failure
mode to the `content-visibility` bug documented in the reveal notes.

**Fix:** delete it, along with its two mock-only tests. If the effect is wanted,
rebuild it on `initScrollReveal`'s defensive pattern rather than this one.

### 10. ⌘K / Ctrl+K does not open with Caps Lock or Shift held

`js/ui.js:682`:

```js
if ((e.metaKey || e.ctrlKey) && e.key === 'k') {
```

`e.key` is `'K'` when Shift or Caps Lock is active, so the shortcut silently does
nothing. Confirmed in the browser: `Ctrl+Shift+K` → overlay stays hidden;
`Ctrl+K` → opens.

**Fix:** `e.key.toLowerCase() === 'k'`, or match on `e.code === 'KeyK'`.

### 11. `initTaglineReveal()` re-injects text as unescaped HTML

`js/ui.js:694–718` reads `tagline.textContent` (which *decodes* entities), splits it,
and writes the pieces back via `innerHTML` without escaping:

```js
spans.push(`<span class="tagline-word" ...>${word}</span>`);
...
tagline.innerHTML = spans.join(' ');
```

The current tagline is `I make things with AI`, so nothing breaks today. But an
ampersand or angle bracket in the copy — `Research & Development` — would round-trip
into raw markup. Every other renderer in the codebase escapes; this one is the
exception.

**Fix:** `escapeHtml(word)`. It is already imported in the same file.

### 12. Minor observations

- **Tab order puts appearance controls before navigation.** On desktop, tabbing from
  the skip link reaches: logo → 3 palette dots → theme toggle → About → CV → … A
  keyboard user passes four colour controls before the first nav link. DOM order
  disagrees with the visual grouping; consider moving `.theme-controls` after
  `#nav-links` in the markup and reordering visually with CSS.
- **`getTopoJSON()` uses a page-relative path.** `js/utils.js:14` fetches
  `'./data/world-110m.json'`. Correct today because the globe only exists on
  `travel.html` at the root — but from any `/projects/*` page it would resolve to
  `/projects/data/…` and 404. A root-relative `/data/…` would be robust to the globe
  moving. (`europe-map.js:464` has the same shape.)
- **`.mnist-layer__canvas` backing stores are fixed at `geom × 2`** regardless of
  layout, so effective DPR ranges from 1.48 (fc2) to 4.48 (conv2) at
  `deviceScaleFactor: 2` — some layers oversampled 2×, others soft. Sizing off the
  laid-out box would be both sharper and cheaper.
- **`clear()` does not reset `_lastSpoken` / `_lastSpokenP`** in `js/mnist-lab.js`, so
  clearing and redrawing the identical digit skips the screen-reader announcement.
