# Site review — 1 August 2026

A review of the site across content, style, accessibility, modernity, design,
performance and general correctness. Findings are ordered by impact, not by
category.

**Method.** Two independent passes. The first read the source, ran `npm test`
(795 assertions, all passing), ran `npm run build` and inspected `dist/` rather
than the source tree, and captured screenshots in both schemes. The second pass
re-derived every claim from scratch rather than accepting it — rebuilding,
re-running the suite, driving all 21 built pages through headless Chromium at
three widths in both schemes, emulating print, rendering PDFs, and accounting
for bytes per page. Claims below carry the evidence that survived that second
pass; two were re-framed and one proposed fix was replaced.

**A note on this file.** It lives at the repo root and names the very files it
flags, so it poisons `grep`-based checks run against the working tree. The
first orphan-image scan of the second pass returned "no orphans" for exactly
that reason. Exclude this file when auditing.

**Framing.** This is an unusually well-built personal site. OKLCH palette
pipeline, `@layer`, `@view-transition`, per-page CSP script hashes,
bfcache-correct teardown, a focus-trapping command palette with `inert`,
cookieless analytics, and a contrast test that measures composited surfaces
rather than trusting `--bg`. Most of what follows is about gaps between the
standard the project sets for itself and where it actually lands.

Verified as already correct, needing no work: font loading (variable woff2,
`font-display: swap`, `unicode-range` subsetting, the two above-the-fold faces
preloaded and the italic correctly not), keyboard access (the skip link is tab
stop 1, 2px visible outlines throughout), `<html lang>`, exactly one `<main>`
and one `<h1>` per page, `width`/`height` on every `<img>`, and lazy-loading
discipline — every page loads exactly `main + theme + utils + preload-helper`
and nothing else, with no `lenet-weights` leak onto pages without `#mnist-lab`.

## 1. Three pages ship as empty shells

The biggest finding, and a direct contradiction of the project's own documented
principle.

`generate-cards` exists because "crawlers and no-JS visitors see real content."
That reasoning was applied to project cards and publications — and then not
applied to three other pages:

| Page | Source | Content in the built HTML |
|---|---|---|
| `cv.html:156,159` | `<div id="cv-timeline"></div>`, `<div id="cv-skills"></div>` | **none** |
| `travel.html:193` | `<div id="unesco-accordion"></div>` | **none** |
| `links.html:132` | `<div id="links-grid"></div>` | **none** |

Verified against `dist/`, not source:

```
grep -c "Vicomtech"   dist/cv.html     → 0
grep -c "link-card"   dist/links.html  → 0
grep -c "Gjirokastra" dist/travel.html → 0
```

`dist/cv.html` is 12 KB of navbar, footer and meta tags with zero career
content. All three are advertised in `public/sitemap.xml`. The CV is the
highest-stakes page on a site whose contact copy says "offer me a job on
LinkedIn" — and it is invisible to Google, to LinkedIn's preview fetcher, and to
every LLM-backed search product that doesn't execute JS. The `docs/cv.pdf` link
is the only indexable career signal.

**Fix:** extend `generate-cards.mjs` (or add a sibling) to bake the three into
their marker blocks. The pattern, the pure builders, and the drift test are
already there — this is applying existing machinery, not new architecture.

## 2. Printing loses most of the page

*Re-framed on the second pass. The first pass filed this as a screenshot-harness
problem; the harness is a symptom, and the real defect is user-facing.*

`[data-animate]` is `opacity: 0` until `initScrollReveal()` adds `.visible`.
That reveal is driven by an IntersectionObserver plus a sweep re-run on
`scroll`/`resize`/`hashchange`/`load`. **None of those fire when a page is
printed without being scrolled first.**

Measured under print emulation:

```
index.html  21 of 21  [data-animate] elements at opacity 0
cv.html      9 of 12
```

Rendering `cv.html` to PDF two ways confirms the ink is genuinely missing rather
than merely reported missing: **4 pages / 233 KB unscrolled vs 4 pages / 402 KB
after scrolling through.** Same layout, same page count, most of the content
blank.

Printing is a first-class use case here — `css/styles.css:4217` carries a
~200-line `@media print` block whose own comment records the last bug of this
family: *"The worst case was the CV, where every job title disappeared."* That
one was about gradient-filled headings. This one is about the reveal, and it is
still open. Land on the CV, press Ctrl+P, get blank space.

**Fix:** one rule in the print block that already exists — no JS, effective
immediately, no interaction with the stagger.

```css
@media print { [data-animate] { opacity: 1 !important; transform: none !important; } }
```

A `setTimeout(revealAll, 2000)` alongside the observer was considered and
rejected: it does not help anyone who prints before the timer fires, and it
dulls the entrance stagger on every page to fix a case that is not about time
passing. The same class of bug — *JS ran, observer exists, nothing ever
scrolled* — also affects headless renderers and social preview fetchers, but
those are served by the CSS rule too.

## 3. `npm run screenshots` has never tested light mode

```
cv-dark.png       vs cv-light.png       → byte-identical
projects-dark.png vs projects-light.png → byte-identical
links-dark.png    vs links-light.png    → byte-identical
```

`scripts/screenshots.mjs:62` uses Playwright's `colorScheme: 'light'`, which sets
`prefers-color-scheme`. But the site **deliberately ignores
`prefers-color-scheme`** — light is opt-in via the toggle only. So the harness
has been silently emitting duplicate dark screenshots for the entire light half
of the matrix.

**Fix:** `ctx.addInitScript(() => localStorage.setItem('theme','light'))` so the
`<head>` bootstrap picks it up. Confirmed working on the second pass — the two
schemes then render distinct `body` background colours.

Combined with #2, the visual-QA harness currently produces 12 files of which
roughly 2 are informative.

*Side note, confirmed by hitting it:* the script hard-codes `chromium.launch()`
with no `executablePath`, which fails in any environment where only the full
Chromium build is present and `chrome-headless-shell` is absent.

## 4. Every page downloads every page's data

`js/main.js:56-61` statically imports six data modules:

```js
import '../data/locations.js';
import { PUBLICATIONS } ...
import { PROJECTS } ...
import { CV_CAREER, ... } ...
import { UNESCO } ...
import { LINKS } ...
```

All six land in the single shared `main-*.js` — confirmed by string probes
against the built chunk (`Gjirokastra`, `Andrej Karpathy`, `Mediapro`,
`gaussian-nerf`, `Bilbao`, `Vicomtech` all present).

Measured rather than estimated: the six modules gzip to **21.3 KB of the
31.3 KB shared bundle — 68% of the shared JS on all 21 pages.**

Concretely: a visitor landing on `now.html` — three paragraphs about a baby and
Dostoevsky — downloads the complete UNESCO world-heritage tree, the 49-entry
blogroll, every travel pin, the full CV, all 37 publications, and all 14
projects.

This is precisely the anti-pattern CLAUDE.md documents for `europe-map.js`
("shipped 10 KB to the twenty pages with no `#europe-canvas`") — the lesson was
learned for code and never applied to data. Each renderer already gates on a DOM
id, so the `import()` can move inside the gate with no restructuring.

## 5. ~1.4 MB of images shipped twice, plus 546 KB nobody references

`copyOgImages()` (`vite.config.js:65`) walks `img/` and copies **everything** to
`dist/img/`, so Rollup's hashed copy in `dist/assets/` and a verbatim copy both
ship. Measured by content hash, not by name:

- **28 files duplicated = 1,378 KB**
- **546 KB never referenced** — six files: `inevent.png` (363 KB),
  `mpi-brain-thumb.webp` (110 KB), and four orphaned thumbs
  (`ufc-octagon-thumb`, `audience-engagement-thumb`, `avatech-thumb`,
  `traction-thumb`)

`img/og/og-forest.png` looks like a seventh orphan and is **not** one — the
per-palette social cards are committed static files, live the moment `active:`
in `data/palettes.yaml` changes. Any allowlist must keep all three.

The plugin's own comment explains it exists solely because `og:image` meta tags
use absolute URLs Vite won't rewrite. That is a handful of files. The project
already established the right pattern one function up — `RUNTIME_DATA_JSON`
(`vite.config.js:44`) is an explicit allowlist, added for this exact reason.
Apply it to images.

Related, smaller: `photo.jpg` (132 KB) and two `ARound_the_world_*.png`
(96 + 133 KB) ship as `<picture>` fallbacks for WebP, which has had universal
support since Safari 14 in 2020. And **`photo.webp` is 1088 px of natural width
rendered at 338 px** — roughly 4× the pixels needed, on the homepage, with no
`srcset`. There is no AVIF, no `srcset`/`sizes` anywhere (a phone fetches the
2032px-wide survey charts at ~685px display), and no `decoding="async"`.

## 6. The project diagrams are baked in three obsolete palettes

*Added on the second pass; missed by the first.*

Four hand-authored SVG diagrams carry hardcoded hex fills that no longer match
anything on the site — and, being fills rather than `var(--*)`, cannot follow a
theme:

```
rag-ingestion.svg / rag-query.svg   #080c14 #0c1020 #6c63ff #00d4ff   ← old indigo/cyan
brand-stadium-pipeline.svg          #120a0a #c2632e #d64550           ← crimson-ish
mnist-lenet.svg                     #0c0908 #e76f51 #f4a261           ← apricot (current)
```

Three different palettes across four files. Rendered and inspected in both
schemes:

- **Light mode** — the RAG diagrams are near-black rectangles dropped into a
  cream page.
- **Dark mode** — they are *cold* blue-black on a warm brown page, with indigo
  and cyan boxes in colours the site's accent ramp never uses. They read as
  screenshots pasted in from another site.

This violates the project's own "don't hardcode colours" rule, and
`test/css-assets.test.mjs` does not reach inside SVG files, so nothing caught
it. Two further defects in the same files: they specify
`font-family="Inter,…"` and `"Segoe UI,…"`, neither of which the site ships
(only `mnist-lenet.svg` uses JetBrains Mono), and the "Embedding Model" label
overflows its box in `rag-ingestion.svg`.

**Fix:** inline SVG (or `currentColor` plus CSS custom properties) so the
diagrams read `var(--*)` like everything else, and switch the type to the two
faces the site actually loads.

## 7. Accessibility

The hard parts are done well — focus trap, `inert` on siblings, focus
restoration, `aria-activedescendant`, `aria-pressed` sync, `role="status"` toast,
`prefers-contrast: more`, `prefers-reduced-motion` everywhere, a skip link as
the first tab stop, and 2px visible focus outlines throughout. Gaps:

- **Card titles are not headings.** `js/render-cards.js:79` emits
  `<span class="project-card__title">`; `:91` emits `<div class="pub-title">`.
  Measured over the built pages: `projects.html` has **h1=1, h2=0, h3=0** for
  14 projects; `links.html` and `now.html` are also h1-only; the homepage has an
  `h1`, five `h2`s and no `h3` at all. Heading navigation is the primary way
  screen-reader users skim a page, and here it does nothing. These are
  `<a>`-wrapped, so `<h3>` inside the anchor is valid and costs nothing
  visually.
- **No automated a11y check in CI.** For a project with 795 unit assertions, four
  E2E files, and a bespoke OKLab contrast harness, the absence of
  `@axe-core/playwright` in the existing E2E suite is the conspicuous hole. It is
  ~10 lines against a page list already enumerated from `dist/`.
- **Theme/palette changes are not announced.** `applyPalette()` fires a toast
  from ⌘K, but the navbar dots and the light/dark toggle change state silently.
- `--text-faint` at ~3.4:1 is logged in TODO.md as a deliberate exception. Fine
  as a decision, but it is the one place the otherwise-rigorous contrast story
  has a hole.

## 8. Content

- **`now.html` is stale and the staleness is load-bearing.** "Last updated 5 June
  2026," against a current date of 1 August. The page says he is "counting down
  to the summer holidays: a trip to Toulouse, and then Italy" — now in the past.
  A now-page's entire contract is currency; a stale one is worse than none. Given
  how much of this repo is generators and drift tests, a test that fails when
  `now.html`'s date exceeds ~90 days is very much in keeping.
- **"I make things with AI" is doing too little.** Likeable and modest, and for a
  Senior AI Engineer whose actual work is broadcast-scale video understanding and
  3D reconstruction, it is the one place on the site that undersells. Everything
  below it is specific and strong; the first line a recruiter reads is the
  vaguest sentence on the page.
- The `#projects` intro says "A random selection" — "random" undersells a curated
  portfolio; the shuffle is a mechanism, not a pitch.
- Minor: "San Sebastián" in the hero, "Donostia, ES" in the CV timeline. Same
  city, but on one screen the inconsistency reads as an oversight rather than
  bilingualism.

## 9. Design

- **The hero's centrepiece is absent on first paint.** `buildNeural()`
  (`js/main.js:958`) defers the CNN scene until the first
  `mousemove`/`scroll`/`touchstart`, while `.hero-cnn-link` — *"The network
  behind this text is a real LeNet-5 — draw it a digit →"* — is shown
  immediately, gated only on `supportsCnnHero()`. The caption asserts a thing
  the canvas has not drawn. Sub-second for a mouse user; permanent for every
  headless renderer, social preview fetcher and print. Gate the two on the same
  event, or reveal the caption from the same `reveal()` callback that fades the
  canvas in.
- **The hero wastes its right half.** Once painted the pipeline is the best idea
  on the site, but at 1440px the name and single CTA occupy the left third, the
  pipeline sits small and dim across the lower middle, and the top-right and
  bottom-right quadrants are empty.
- **Equal-height grid rows leave large dead space.** On `projects.html`, "Draw a
  digit, watch a LeNet-5 read it" has ~170px of empty card below its text
  because the row height is set by the Gaussian-splatting card's much longer
  description. Either `align-items: start`, or clamp descriptions with
  `-webkit-line-clamp` on listing pages (full text lives on the detail page
  anyway).
- **`cv.html` breaks its own alignment rule.** CLAUDE.md: "every
  `.section-header` is **left-aligned**." The eyebrow and `<h1>` are; the
  "Download PDF + Career/Education legend" row directly beneath is centred.
  Visible as a kink in the left edge.
- Eight ad-hoc `max-width` breakpoints (1080, 1024, 900, 760, 720, 680, 640,
  480). The card grids in particular are asking for container queries — they are
  the same component at three different container widths.

## 10. Modernity

Already there: OKLCH, `@layer`, `@view-transition`, Speculation Rules prerender,
`dvh`, `scripting:` and `pointer:` queries, `prefers-contrast`, `inert`.

Worth adding, cheapest first:

- **`text-wrap: pretty`** on prose and **`balance`** on headings — one
  declaration each, visibly better ragging on a serif-body site. Currently zero
  uses.
- **`color-mix()`** would collapse a chunk of the hand-tuned translucent-surface
  ladder that `textSurfaces()` in the contrast test has to enumerate by hand.
- **Container queries** (see above), **`:has()`** (zero uses),
  **`@starting-style`** for the toast and command-palette entry.
- **Performance budget in CI.** The build gates on E2E, CSP hashes, card drift
  and analytics pixels — but nothing fails when the shared bundle grows. Given
  #4, a byte budget on `dist/assets/main-*.js` would have caught it.
- **`llms.txt`.** `robots.txt` explicitly welcomes AI crawlers. The emerging
  convention for *telling* them what is here is `/llms.txt`. Rated lower than
  the first pass rated it — it is not a ratified standard and crawler adoption
  is thin — but it is the natural companion to fixing #1, since right now an AI
  crawler that welcomes itself in finds three empty pages.

## 11. Housekeeping

`npm audit` reports 3 high-severity advisories — `postcss`, `vite`
(8.0.0–8.0.15), and `sharp` (<0.35.0, libvips CVEs). All dev-time only; none
reach the deployed static output. `npm audit fix` clears postcss and vite
non-breaking; sharp needs the major bump.

## Investigated and dismissed

Recorded so they are not re-opened.

- **`frame-ancestors` console error on all 21 pages.** Real, and browsers do
  ignore the directive when delivered via `<meta>` — but it is a known,
  deliberate decision, suppressed with a comment at
  `test/e2e/harness.mjs:243`. The only substantive remark left is that the
  directive is *inert*: it delivers no clickjacking protection, GitHub Pages
  cannot set the header that would, and dropping it from the meta would silence
  a console error every visitor sees. Cosmetic either way.
- **Empty `<meta name="description">` on every page.** An artefact of a
  single-line `grep` against a wrapped attribute. The descriptions are present
  and well-written.
- **`lenet-weights` loading on pages without `#mnist-lab`.** Probed
  per-page; the gating works exactly as documented.

## Suggested order of work

1. **SSR the CV, links and UNESCO pages** — highest impact, existing machinery,
   and it is the site not honouring its own stated rule on its most important
   page.
2. **The print rule** — one CSS line, closes a user-facing bug.
3. **Fix the screenshots harness** (light mode + chromium path) — it is the tool
   you would verify 2 with, and visual QA currently returns black rectangles.
4. **Re-theme the four diagram SVGs** — visible on every visit to those pages,
   in both schemes.
5. **Move the six data imports behind their DOM gates** — 21 KB gzip, 68% of the
   shared bundle.
6. **Allowlist `copyOgImages`, delete the six orphans** — ~1.9 MB off the deploy.
7. **`<h3>` on card titles + axe-core in the E2E suite.**
8. **Refresh `now.html`**, and add a staleness test so it cannot drift again.

Items 1, 5 and 6 are all cases where the project already has the correct pattern
documented and applied elsewhere — the good kind of finding, because the fixes
are mechanical rather than architectural.
